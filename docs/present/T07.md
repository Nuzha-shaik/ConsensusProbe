# Task T07: Benchmark Task Seed Selector

## Goal
Build a Benchmark Seed Selector allowing a presenter or evaluator to pick from pre-registered held-out evaluation tasks (seeds 5000–5099) to inspect different ambiguity categories and verify deterministic repeatability.

---

## Files Whitelist
- `frontend/src/components/showcase/BenchmarkSeedSelector.tsx` (new component)
- `frontend/src/App.tsx`

---

## Contract

### Component Props: `BenchmarkSeedSelector.tsx`
```typescript
export interface BenchmarkTaskPreset {
  seed: number;
  ambiguityType: 'duplicate_id_vs_name' | 'missing_strategy' | 'category_granularity' | 'recalculate_basis' | 'type_coercion' | 'none';
  isAmbiguous: boolean;
  title: string;
  expectedDisagreement: number;
  expectedQuestions: number;
}

export interface BenchmarkSeedSelectorProps {
  currentSeed: number | null;
  onSelectSeed: (seed: number) => Promise<void>;
  isLoading?: boolean;
}
```

## Micro-Steps in Order

### Step 1: Create `frontend/src/components/showcase/BenchmarkSeedSelector.tsx`
- Layout: Compact card with a grid of quick-select buttons or a dropdown selector.
- Visual elements:
  - Pill badges displaying ambiguity category (e.g. `DUPLICATE ID`, `TAX BASIS`, `CLEAN`).
  - Expected divergence indicator: `Expected d = 0.38` vs `Expected d = 0.00`.
  - Active seed highlighted with an indigo ring (`ring-2 ring-indigo-500`).
  - 1-click execution button: "Load Benchmark Task" triggering `onSelectSeed(seed)`.

### Step 2: Integrate into `frontend/src/App.tsx`
- Add state `activeBenchmarkSeed: number | null` in `App.tsx`.
- Implement `handleSelectBenchmarkSeed(seed: number)`:
  - Sets active seed.
  - Loads sample dataset corresponding to the task seed or runs client consensus with the seed.
  - Switches to `workspace` tab to show the multi-agent execution pipeline.
- Render `<BenchmarkSeedSelector />` in the `Upload / Ingestion` tab as an academic alternative to manual file upload.

---

## Edge Cases & Failure Behavior
- Seeds < 5000 are DEV seeds; seeds >= 5000 are TEST seeds. The UI cleanly labels TEST seeds to reassure the guide that evaluations are on held-out data.
- While loading, all preset buttons are disabled to prevent duplicate concurrent runs.
