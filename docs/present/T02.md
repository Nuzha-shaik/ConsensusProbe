# Task T02: Presentation Mode Header & Demo Scenarios 1 and 2

## Goal
Add a dedicated "Guide Presentation Mode" control strip to the dashboard with 1-click execution for Scenario 1 (Unanimous Consensus) and Scenario 2 (Semantic Conflict Gate), displaying real measured latency.

---

## Files Whitelist
- `frontend/src/components/showcase/PresentationModeBar.tsx` (new component)
- `frontend/src/lib/clientEngine.ts`
- `frontend/src/App.tsx`

## Contract

### Component Props: `PresentationModeBar.tsx`
```typescript
export interface PresentationModeBarProps {
  activeScenario: 1 | 2 | 3 | null;
  onRunScenario: (scenarioId: 1 | 2 | 3) => Promise<void>;
  isExecuting: boolean;
  latencyMs: number | null;
  tauD: number;
}
```

### Client Engine Scenario Fallback: `clientEngine.ts`
```typescript
export function clientRunScenario(scenarioId: 1 | 2 | 3): {
  scenario_id: number;
  title: string;
  seed: number;
  status: 'applied' | 'needs_clarification' | 'canary_alert';
  consensus_score: number;
  tau_d: number;
  questions_asked: number;
  latency_ms: number;
  dataset_preview: Record<string, string>[];
  patch_summary: { deleted_rows: number; edited_cells: number; flagged_rows: number };
  disputed_cell?: {
    row_id: number;
    col: string;
    proposals: Record<string, string>;
    reason: string;
  };
}
```

## Micro-Steps in Order

### Step 1: Add `clientRunScenario` to `frontend/src/lib/clientEngine.ts`
- Implement `clientRunScenario(scenarioId: 1 | 2 | 3)` with deterministic mock logic.
- Record start time with `performance.now()` and return elapsed `latency_ms`.
- For `scenarioId === 1`: returns `status: 'applied'`, `consensus_score: 0.0`.
- For `scenarioId === 2`: returns `status: 'needs_clarification'`, `consensus_score: 0.3800`, attaches `disputed_cell`.
- For `scenarioId === 3`: returns `status: 'canary_alert'`, `consensus_score: 0.4200`.

### Step 2: Create `frontend/src/components/showcase/PresentationModeBar.tsx`
- Layout: Full-width banner above the main dashboard cards.
- Dark theme card (`bg-slate-900/90 border border-slate-800 rounded-2xl p-4 shadow-sm`).
- Top row: Title "GUIDE PRESENTATION DEMO SUITE", status pill with `tau_d = 0.00`, and live latency display if non-null (`e.g., "Measured Engine Latency: 142 ms"`).
- Button 1: "Scenario 1: Unanimous Agreement (d = 0.00)" (Emerald theme, `CheckCircle2` icon).
- Button 2: "Scenario 2: Semantic Conflict (d = 0.38 > τ_d)" (Amber theme, `AlertTriangle` icon).
- Button 3: Placeholder for Scenario 3 (wired in T05).
- All buttons disabled while `isExecuting` is true.

### Step 3: Wire into `frontend/src/App.tsx`
- Add state in `App`:
  ```typescript
  const [activeScenario, setActiveScenario] = useState<1 | 2 | 3 | null>(null);
  const [scenarioLatency, setScenarioLatency] = useState<number | null>(null);
  const [isScenarioLoading, setIsScenarioLoading] = useState<boolean>(false);
  ```
- Implement `handleRunScenario(id: 1 | 2 | 3)`:
  - Try fetching `${API_BASE}/api/scenarios/run/${id}` with a 2-second timeout.
  - Fall back to `clientRunScenario(id)` if network/backend is unavailable.
  - Update `consensusScore`, `cleanStatus`, `patchSummary`, `scenarioLatency`, and `activeScenario`.
  - If scenario 2, auto-open clarification dialog.
- Render `<PresentationModeBar />` at the top of `{activeTab === 'dashboard'}` view.

---

## Edge Cases & Failure Behavior
- Backend offline: smoothly falls back to `clientRunScenario` without flashing an error.
- Rapid multiple clicks: buttons are disabled during execution (`isExecuting={isScenarioLoading}`).
- No fake latency strings: latency must come directly from `performance.now()` measurement.
